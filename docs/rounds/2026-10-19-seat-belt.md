# The seat belt round (Oct 19 2026)

Branch `oct19/seat-belt`, over master `c64e2587` (the Learning vault, live). **Not pushed.** Front end only: no Firestore rule, index, Cloud Function, cron or Mindbody change.

## Where it came from

AJ's per-client FileMaker import chat, Oct 19 2026. Judy Gibson's (Strongsville) Pulldown chart has a box that just says "Belt": `Pulldown: B- 4 S- 4 G- 3 Belt`. Journey's Pulldown had nowhere to put it (Gap, Back Pad, Seat, Handles), so the import held it back. AJ: **"allow machines to have a seatbelt toggle to them"**.

## What AJ decided

The first plan asked three questions (who adds it, is "off" the same as never set, where does it show). AJ answered the first two in his own words:

> "every machine could/should have a seatbelt now if the client chooses to use it or if the machine has it installed is another question that the studio needs to answer
>
> SOme clients weight is so low the seatbelt is not required or their form has progressed to a point they dont need the seatbelt
>
> On/off/Not needed"

The revised plan asked two more, and he picked the recommended answer to both: **"Aa Ba. Build the seat belt as planned on its own branch, including the one new field for the studio's answer. Don't push."**

- **Every machine carries a seat belt**, built in. Nobody has to add it machine by machine.
- **A trainer picks one of three for each client: On · Off · Not needed.** Off: the client chose not to wear it. Not needed: the trainer judged it unnecessary (a light load, or form that no longer needs it). Nothing saved means **not recorded**, which is every client before this round. It is never read as Off, and never counted as one of the Now Bar's "not set" dials.
- **The studio says whether each unit has a belt**: one line in the machine editor, "Seat belt on this unit: Yes / No". **(Ba)** Until it is answered, the belt shows; No takes it off that unit's card. A value already saved for a client stays on their record if a studio later says No.
- **(Aa) Where it shows.** On the card it is a tile after the machine's own dials, and the tile is the switch: three buttons, the chosen one blue. A tap is a change like any dial's: "was On", the change strip, Why? asked and never required, and Save closes the card. On the Now Bar it joins the settings line once recorded: "Gap 3 · Back pad 4 · Seat 4 · Belt on".

## The data

- **The client's choice** is one more value in `clientMachineSettings/{clientId}_{machineId}.settings`, under the key **"Seat belt"** (the key and the label are the same words; dials on the floor are saved under their labels). Same Save, `settingHistory` row, journal copy and Undo as every dial; on a set's settings snapshot, and on an open session's held set-up, like every dial. No new structure.
- **The unit's answer** is the one new field, `hasSeatBelt` (boolean) on a machine's definition (AJ's OK, "including the one new field for the studio's answer"): on `machines/{id}` for the standard (administrators), in a copy's `overrides` or an own machine's `definition` on `studios/{s}/roster/{id}` (the studio). A studio field in the template boundary (`lib/machine-template.ts`): the hardware is the studio's. The rules check neither a dial's type nor a definition's keys, so nothing there changed.
- **Readers.** The client's choice: the machine card, the Now Bar and the phone card, the grid's rail, Programming → Setup, the setting changes list and the Staircase's set-up lane. The unit's answer: `toFloorMachines` → `buildFields`, which decides whether the belt is on that unit's dials; Compare and the save's toast name it ("seat belt").

## What it never does

- **Machine fit never sees it.** `toFitFields` and `toFitRow` leave it out, so it is never suggested, never "worth a look", never in a combination, never pooled as evidence. A belt is not a position that follows a body, and "nobody else here goes without the belt" would read as coaching. (`toFitRow` is also bundled into the web service's machine-fit rebuild; it leaves the belt out there too from the next deploy, which is the same rule.)
- **"How it's used" never shows it.** The weekly trends job (server, unchanged) still counts it like any setting, but its choices beside a median best load would read as advice ("Not needed lifts more"), so `machine-trends/present.ts` drops it from the page.
- **No studio standard, no Use.** Nobody sets a standard for the belt, so "Use studio standard for all" never fills it.
- **Set up never stops on it.** It is three buttons, not typed: it is never the first empty dial, and Enter never goes to it.

## The paste box

FileMaker prints the belt as a bare word, so `machine-fit/shorthand.ts` places it by its own rule: its name alone is **On** ("Belt", "Seat belt"), "No belt" is **Off**, and a word after it says which ("Belt: off", "Belt N", "Belt not needed"). It answers only to its whole name, never to a letter or its first word. That matters because the reader gives every two-word dial its first word as a nickname, so a "Seat belt" answering to "Seat" would have taken "S- 4" off the seat. "G- Belt" is an empty gap and then the belt, never a gap of "Belt". On a unit with no belt, "Belt" is kept as a leftover (a note on the machine), as before.

**For the import chat:** Judy's line now reads `Back Pad 4 · Seat 4 · Gap 3 · Seat belt On`. Once this is live and the import tool hands the belt to the reader and the save planner (`seatBeltField()` from `src/features/equipment/seat-belt.ts`, appended to the machine's fields), "Belt" lands on it as a `legacy` value.

## What the review found (Opus, read only), fixed

1. **"No-belt" read as On.** The dash rule makes "No-belt" a label and its value before the belt rule sees it; `beltAt` now steps over one separator (and reads "without belt", "w/o belt" as Off).
2. **Setup hid the belt** on a machine with no dials, and a belt recorded alone in Check's one-line row; both show now, and its paste box reaches a dial-less machine.
3. **"Belt N A- 3" read as Not needed** ("N A" folds to "na"); two words after the belt are read only for "not needed" / "not required".
4. **"Handles No belt" gave Handles "No".** The no-separator path now sees the belt starting.
5. **The belt alone counted as the first set-up** (the history's "Initial setup", the Now Bar's wording, All Machines' sort); it no longer does.
6. **"Belt Not needed" would be cut short** on the profile chart's boxes; the boxes leave the belt out.
7. Smaller: Set up waits for the machine's own dials; one test for "is this the belt" (`isSeatBeltField`, key or label) everywhere a dial list is read; the catalog review names a seat belt difference as hardware.

The screenshot pass (`harness/seat-belt/`, not committed) found one more: in the portrait card's 234px tile "Not needed" broke mid-word ("Not neede / d"); each button is now as wide as its word and the three share one row.

## Choices Claude made (say if you disagree)

- **Off vs Not needed** read as above (the client's choice vs the trainer's judgement).
- A watched session (read only) shows the belt's word, or "Not set" when nothing is recorded, the word every empty dial uses there.
- Tapping the choice already picked does nothing; Cancel on the strip puts a mis-tap back. A recorded belt is never cleared back to "not recorded" from the card.
- A dial a studio named "Belt" or "Seat belt" itself (none existed on Oct 19 2026, read from production) is treated as the belt, and the built-in one is not added beside it.
- The profile chart's position boxes (the small boxes under Gap) leave the belt out: they are one line, and "Belt Not needed" would be cut short there. The row still says it to a screen reader, and the Now Bar and the card show it.
- The belt recorded alone is never a set-up: the Now Bar keeps "Set up · 3 not set", the dials' first save is still the first set-up, and a save of the belt alone is "Save Seat belt On".
