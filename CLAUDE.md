# Journey System (Max Strength App) — read this first

Journey is the coaching app for **Max Strength Fitness** studios: trainers record workouts, machine settings and notes on iPads on the gym floor; studio leaders run the studio from the same app. It replaces the Claris FileMaker system the studios use today and syncs people, bookings and contracts from **Mindbody**.

How the business works (packages, renewals, roles, where data lives) is in **`docs/business/`**. Read the relevant page before building anything that touches clients' packages, renewals or permissions.

**`docs/START-HERE.md`** is the orientation page — the three systems and who owns what, the map of the folders, the project's invented vocabulary, how a change reaches an iPad, and the rules that must never break. It is written for AJ (who does not write code), so it is also the fastest way for a new session to get the shape of the project before diving into this file's detail.

**What a session is** — twenty minutes, one set to failure on five to eight machines, an iPad in the non-dominant hand that is set down at every machine and looked at twice per machine. The trainer's clicker counts reps; the app is a guide for set-up and a log for outcomes, never a coach, and never suggests a progression. Read **`docs/business/the-floor.md`** before touching the Active Session, the Now Bar, the briefing or the Wrap-up (the post-session screen). It opens with **Ken Hutchins' definition of exercise**, which is the source every rule below is downstream of — if a change is not within that definition, it is not within the method, and naming the clause it breaks is the fastest way to say why.

**Journey is not a fresh start.** The studios are mid-migration off FileMaker, and a roster during that period is a mix of brand-new clients and clients with several hundred sessions behind them. A client's history did not begin when Journey first saw them: an empty Journey history means "no detail here", never "this never happened". Read **`docs/business/migration-and-prior-history.md`** before building anything that counts, dates, averages or trends a client's history.

## Environments

- **Production** Firebase project `gen-lang-client-0731527386`, named database `ai-studio-32cbbdcc-6e08-4770-9665-867c68878efa`. The project id inside `firebase-applet-config.json` is not the live one.
- The local `.env` points at **production**, so local writes change real client records.
- The live app is a Render web service (`maxstrength-app-beta.onrender.com`). **A push to `master` does NOT deploy it.** Render can't read the repo (its build log says so), so no push reaches it: every deploy is AJ pressing **Manual Deploy** on the web service and **Manual Build** on BOTH cron jobs (`journey-cron-renewals`, `journey-cron-leaderboards`). A cron left out keeps running its old commit (push-to-deploy comes back once the repo's owner installs Render's GitHub app). Cloud Functions and Firestore rules deploy separately with the Firebase CLI.
- Four studios on two Mindbody sites: westlake, Strongsville and Willoughby share site **29068** (locations 3, 5, 4); Solon is site **5746957** (location 1). The schedule pull-sync runs one studio at a time.

## Decisions already made — don't change them without asking

Each is the rule, in AJ's words wherever AJ gave them. **More** opens its full entry in `docs/DECISIONS.md` (the history, the files, the tests that hold it): read that before changing anything a decision covers.

**Product**
- iPad-first, portrait and landscape. Nothing tappable under 40px; hover is never the only way to find something; names are never truncated.
- **Corporate owns the method, so corporate reads it before adopting it** (the catalog gate, Sep 20 2026). Publishing a studio's machine makes its words Max Strength's on every floor, so an administrator reads it in the catalog editor first, and publishing is refused while it is missing anything the floor would coach wrong. The one place the app holds a write, the opposite case from "never block a save", which protects a trainer mid-session. [More](docs/DECISIONS.md#corporate-owns-the-method)
- **Sentences, not scores.** Every claim a screen makes has a named minimum sample, and below it the screen says "not enough data yet".
- A confident wrong number is worse than a missing one (the "In Journey since" rule).
- **Operations says it once, and says less** (AJ, Oct 3 2026: "there's just so many words on there. It's really overwhelming"). A page leads with one line of counts; what it can't judge yet is ONE note at the top; a row is one line, its how-to on its (i); no captions under headings; empty sections share one "All clear" line. A count is not a score: the proof stays one tap away. [More](docs/DECISIONS.md#operations-says-it-once)
- **Sessions left means left in the contract; given sessions are extra, beside it** (AJ, Sep 26 2026): "36 left in contract · +12 extra" (`sessionsSplit`); a contract paid monthly says "on hand", never left. **Left and recorded are different numbers, never mixed** (AJ, Oct 2 2026: "A client could have 42 sessions in their package but only have 40 sessions by the end of their package due to late cancels"). A late cancel is a mark on a booking nobody logged, tallied beside visits, never inside them. Given sessions count toward the renewal. [More](docs/DECISIONS.md#sessions-left)
- **Every number has a reader.** A field we write is read by at least one screen, report or job; a write with no reader is a bug to fix, not a field to delete (`docs/business/data-and-metrics.md`). The session's snapshot of the client (age, occupation, activity, clinical profile) is deliberate, for cohort analytics. Every cohort metric has a named minimum sample, cells of at least five clients (`CELL_MIN_CLIENTS`), no clinical data a trainer can read per person, and never ranks. [More](docs/DECISIONS.md#every-number-has-a-reader)
- **Prior history is real history, and it comes from Mindbody, not FileMaker** (AJ, Oct 2 2026: "we just need to know how many sessions they have TOTAL and when was their first session"). Total sessions = before Journey + Journey's (`src/lib/session-total.ts`). Before Journey is guessed from Mindbody's visit count and confirmed once by a trainer on Account; until then screens say "from Mindbody, not yet confirmed", and milestones wait. Never call a client new off a low Journey count. Every sentence about a client's past comes from `src/lib/history-claims.ts`. [More](docs/DECISIONS.md#prior-history)
- **A FileMaker session counts everywhere, tagged "from FileMaker"; trend and average measures go Journey-era only later, by one word** (AJ, Oct 21 2026). `src/lib/session-era.ts` derives the era at read time and is the one place it is read; `TREND_ERA` is the switch. [More](docs/DECISIONS.md#session-eras)
- **A client's first day at the studio is set by a person, once, and every anniversary counts from it** (AJ, Sep 29 2026: "we need to make sure setting a client's anniversary for their first day in the studio is intuitive"). `client.firstStudioDay`, set on Account → First day at the studio, beats every inferred date (`src/lib/client-since.ts`); until it is set, a screen says the guess and where it came from. Nothing writes it for you. [More](docs/DECISIONS.md#first-day-at-the-studio)
- **A client's pronoun follows their Mindbody gender** (AJ, Oct 15 2026: "We defiently need to read client gender"): Male he, Female she, blank or Other the first name or they; a sentence that reads well with no pronoun keeps none, and a wrong gender is fixed in Mindbody. Built: `pronounsFor` (codex `kit/pronouns.ts`) is the one place it is read. [More](docs/DECISIONS.md#no-guessed-gender)
- **Names are never truncated, and a guard holds it** (Sep 29 2026): `src/lib/names-wrap.test.ts` reads the stylesheets and screens the audit found cutting a name short (the live session's bar and Now Bar, the calendar, history, My Profile's lists, the top strip's studio name, the profile's sub-tabs) and fails on an ellipsis, a line clamp, or nowrap with hidden overflow; a row that must hold a wrapped name has a minimum height, never a height.
- **The phone is the minimalist mode** (AJ, Oct 19 2026: "get rid of a lot of the features"): rows, My week, one switch. [More](docs/DECISIONS.md#the-phone-is-the-minimalist-mode)
- **In-app only, for now** (AJ, Oct 15 2026: "this is not a NEVER do its a we arent doing yet"). **Never book a Mindbody visit** ("2.50 fee is crazy for that").
- **The standing week is a check, never a booking** (AJ, Sep 27 2026). A trainer proposes their usual week, a leader agrees it, and Journey checks the next 7 days of Mindbody bookings against it and says where they differ. It never writes a hold, a booking or availability to Mindbody. A day not read in full, or read offline or only from cache, is "can't tell", never "open". Days away block slots out ("if someone has a vacation then it should block it out"); colleagues see each other's agreed week. [More](docs/DECISIONS.md#the-standing-week)
- **Openings is a screen a person opens: it never books, never pings, and says "room" only where it can stand behind it** (AJ, Sep 27 2026). A past day counts only if Journey read it in full; every offer ends "Check it in Mindbody before you promise it. Journey doesn't book." A Mindbody "Unavailable" block is never a booking (`isStaffBlock`). No Mindbody call and no new index ("i just dont want a big mindbody bill or firestore bill popping up"). [More](docs/DECISIONS.md#openings)
- **How fresh each Mindbody fact must be** (AJ, Sep 26 2026). Today's and tomorrow's bookings within about 30 minutes; days 3–30 each morning; packages when a sale happens; client details when they change. **Nothing syncs a studio's clients on a timer before its cutover** ("we don't randomly sync all of our clients and have a big Mindbody bill"). A timer asking Mindbody more often needs AJ's OK; a schedule's pull rate is administrators' alone. **One Mindbody read serves a whole site** (Oct 12 2026); an older answer never overwrites or cancels a newer booking. [More](docs/DECISIONS.md#mindbody-freshness)
- **A studio's numbers have head office's default beneath them** (AJ, Sep 28 2026: "let the admins assign the default within the app"). A number that is a studio's own choice is a setting in `src/features/studio-settings/registry.ts`, never a constant in a screen: the studio's own, else Max Strength's default, else the app's. A screen asks `useStudioSettings`; an unusable value is skipped, never bent. [More](docs/DECISIONS.md#studio-settings)
- Use the design tokens (`src/index.css`, `equipment.tokens.css`, `admin.tokens.css`, or a feature's own copy of `equipment.tokens.css`, held to it by a test); no raw hex and no Tailwind palette colour in a component (`neutral-ramp.test.ts` counts the rest, and the count only goes down). Words 4.5:1 or more; control edges and icons that mean something 3:1; small words never in the faint ink. The red kaizen mark is reserved for rep quality. [More](docs/DECISIONS.md#design-tokens)
- **The Navy Frame: the logo's colours, each with one job** (Oct 4 2026; AJ: "use our colors from the max strength logo"). The frame (header, bottom bar, status bar) is the logo's navy in both modes. Light is calm daylight with nothing pure white; dark is the studio navy. **Blue is yours, picked and in session, and every Save and selection; orange is only now and go** (Start, Finish, a screen's one loud action), never with white words. Crimson is Critical, destructive and rep quality only. No studio accent colour. [More](docs/DECISIONS.md#the-navy-frame)
- **Type and depth: "Refined Lift"** (Oct 4–5 2026; AJ: "borders and headers just needs a little bit of weight and depth"). Titles are upright Saira Condensed; the slanted capitals live in exactly four places (the studio's name, Start session, In progress, the front door). Buttons keep the firm 3:1 outline, with a lighter face, a small lift and a press; a chip a trainer taps has the firm edge too. Nothing in the Active Session is under 11px. Shadows are navy, never black. [More](docs/DECISIONS.md#type-and-depth)
- Dates are the studio's Eastern day (`src/lib/studio-time.ts`).
- **Anything a trainer RATES about a client is the Dial; anything they WRITE carries a Loudness** (reporting round, Sep 16), which says where the note goes: Profile only · Next time · Critical (Oct 18 2026). No screen builds another rating control or another priority vocabulary. The living assessment is **Pulse** on every label (code and Firestore still say check-in / subjective).
- **A note is filed by what it is FOR, and reaches whoever acts on it** (the notes round, Oct 3 2026; AJ: "we need to know how to correctly file this into their note section on their profile, so that way we know how to act on it later"). Coaching & equipment · Health · Incident · Retention · FORD / Life · Preference. Health, Incident and Retention reach the leaders on Operations → Today. A Heads up is read out at four SESSIONS, not days. Nothing is required to save. A leader's notes about a trainer stay private to the leader; a machine's notes are one dated list per machine. [More](docs/DECISIONS.md#note-categories)

The three zones (Open · Standing context · Resolved) are derived, never set. Dismissal is per trainer, private, and undone by any update; nothing is hidden without a way back. - **A stash of routines; slots A and B hold two** (AJ, Oct 23; [before](docs/DECISIONS.md#the-routine-builder)). A planned B phases in. [More](docs/DECISIONS.md#the-routine-library)
- **A new client's start is a first draft, and the consult is not Routine A** (Oct 8–9 2026; AJ: "everyone starts at different strength levels with different body types and also different contraindications"). Head office makes the starting routines and each studio chooses; gender is used nowhere. The consult's machines are day one and Routine A starts empty. Can't do is the client's, read by A and B. The Academy's starting range is a reference beside the weight, never typed in. A reason for a change is asked, never required, everywhere. [More](docs/DECISIONS.md#a-new-clients-start)
- **An open session is a FileMaker session, with the routine builder on demand** (AJ, Oct 9 2026: "feel most like a filemaker session"; "1b 2a 3a"). Every machine on the floor shows and + builds today's list; the session records only what was added, never the floor. Start from a routine… lays one on today's list and writes no routine. Set up opens the machine card on the first empty dial. Settings typed before the client is chosen stay on the session (`heldSetup`) and reach the client with the sets in Who's this?'s one batch. [More](docs/DECISIONS.md#the-open-session)
- **My Studio → Team is people and standards; Relay is for the trainer between clients** (AJ, Sep 27 2026: "Relay must prioritize the trainers transitioning between clients. Leaders running the day have operations and the hub to rely on."). A leader-only view does not go on Relay. Each person's week is shown by name, never ranked. Who is on the team is "everyone who works there" (`src/lib/who-works-here.ts`). [More](docs/DECISIONS.md#team-and-relay)
- **My Studio is where you run the studio; Operations is where you look at it** (AJ, Sep 18 2026). My Studio answers "how can I help the team right now?"; Operations answers "where are we going wrong, and where are we going right?" A studio's settings are edited on My Studio → Studio and nowhere else ("Leaders edit it; trainers can view it read-only"). The one exception: Operations → Floor mounts the same floor editor, one implementation with two doors. [More](docs/DECISIONS.md#my-studio-and-operations)
- **Operations is split in two** (Operations overhaul, Sep 19 2026). Operations is studio leaders', always one studio, seven places (Today · Week · Month · Ahead · Clients · Team · Setup); the Admins dashboard (the catalog, the standard, every location, Limbo, system tools) is administrators' and the founder's only. **Nothing on Today is a score**: a sentence with its proof, an action and a door. A cancellation reads as a reschedule only for a real rebook (`isRealRebook`). **Nothing pings anyone**; sharing a note is always a copy, never a visibility flag. [More](docs/DECISIONS.md#operations-and-admins)
- **One rule for where a client is** (Sep 28 2026; Inactive Oct 1 2026). New · Settling in · Steady → MIA (Drifting · At risk · Lapsed) → Inactive, with Away · Back · Unknown beside them, on leader screens only (`src/features/admin/journey/states.ts`); the lines are studio settings. A client Journey can't judge is Unknown, never Lapsed off a low count. Inactive comes by time with nothing booked, or a leader's mark with a reason (AJ: "a client is active>MIA>inactive and studios can customize time or manually set clients inactive"); a booking brings the client Back. [More](docs/DECISIONS.md#client-states)
- **Trainers offer; leaders assign** (AJ, Sep 28 2026: "Trainers can post offers where other trainers can pick it up but leadership can just directly assign"). A leader's job arrives already that person's, with "I can't". An open question about a client is a thread on their record, and the answer closes it (`studio-tasks/question-trail.ts`). [More](docs/DECISIONS.md#trainers-offer-leaders-assign)
- **Recognition, never ranking, inside a studio.** Kudos are shown per person; no points, badges, per-person streaks or leaderboards; people are listed in name order everywhere (AJ: "the hub should have everyone"). Studios may be compared only on measures with a named minimum sample. [More](docs/DECISIONS.md#recognition-never-ranking)
- **Max Strength owns the method; a studio owns its hardware** (Sep 20 2026). The method (movement, cadence, turnarounds, cues) is the product and every floor reads the same words; a studio owns its unit (name, positions, dials, starting load, photo). **A studio may change anything on its own copy, safety included** (AJ: "Yes studios need to be able to customize their stuff safety is definitely a worry but are trusted"); a safety line comes off only with a recorded reason, and head office sees every difference. `src/lib/machine-template.ts` says whose words a field is. [More](docs/DECISIONS.md#method-and-hardware)
- **Sharing between studios is the studio's offer and an administrator's decision** (AJ, Sep 28 2026: it "should submit to admins first for review"). "Offer to all MSF studios" reaches no one until an administrator shares it; only an administrator sets `shared`. A studio's own machine knowledge is read only by the people who work there. [More](docs/DECISIONS.md#sharing-between-studios)

**Data**
- Mindbody owns people, bookings and contracts; Journey owns coaching data. A Mindbody client lives at `clients/{mindbodyClientId}` (no name matching, ever), except the second person on a shared number, at `clients/{siteId}-{mindbodyClientId}` (`src/lib/mindbody-site.ts`). A record's Mindbody id is always the `mindbodyClientId` field, never parsed from the doc id. [More](docs/DECISIONS.md#mindbody-owns-people)
- Every query names the studios it reads (`src/lib/tenancy.ts`). Sessions are scoped by **client**, not studio.
- Never write to a collection from inside a listener on that same collection. A failed read means "unknown", never "empty". No per-client queries in a loop.
- **Every query ships with its index** (speed round, Oct 5 2026). Production Firestore is the Enterprise edition: no automatic indexes, and a query without one silently scans the whole collection, billed by the byte. A new query adds a composite index to `firestore.indexes.json` (never `fieldOverrides`); `src/lib/firestore-indexes.test.ts` fails without it. [More](docs/DECISIONS.md#query-indexes)
- **A tap on the floor never waits on the network** (speed round, Oct 5 2026). Start, Discard, Back to Hub, the machine menu's Save and Undo, and the set writes issue their writes and move on; a refusal comes back as a toast. - Keep running totals (`trainerTally`, `machineStats`, trainer rollups) instead of re-reading history when a screen opens.
- **A projected date counts from the day Mindbody counted, and says its range** (AJ, Oct 7 2026, "2a"). Sessions left is Mindbody's count at its last pull; the run-out day and the renewal conversation count from that day (`projectionStart`) and say "around" with a range. Mindbody's Remaining does not drop when a visit is booked (checked Oct 7 2026), so nothing takes booked visits off a second time. [More](docs/DECISIONS.md#projected-dates)
- **A client's machine maps live in their own document, never on the client** (Oct 6 2026, AJ's explicit OK). `currentMachineMetrics` and `machineStats` are at `clients/{id}/machineTotals/current`; every reader merges both sides through `mergeMachineTotals`, every writer goes through `machine-totals/store.ts`, and a document still loading is unknown, never "nothing on file". - **Auto-renew is decided in one place** (`src/features/renewals/auto-renew.ts`, Sep 25 2026): Mindbody's flag, else the trainer's mark on the profile, else the package's answer, else the studio's (default ON; the corporate studios turn it off). ## Roles

`ROLE_LABELS` in `src/types.ts` is the vocabulary: **Life Transformer** (a trainer), **Head Trainer** (`HeadTrainer`, its own label since Sep 27 2026), **Studio Leader** (`StudioLeader`), **Studio Owner** (`StudioOwner`), **Franchise Owner** (`Owner`, `FranchiseOwner`), **Founder / Overseer**, **System Administrator**. Three tiers (AJ, Sep 18): the **studio tier** runs one studio — head trainer, studio leader, studio owner at that studio, or a trainer with **the grant** (`Trainer.managedStudioIds`); the **owner tier** runs the studios an administrator marked in `ownedStudioIds`, and their home, exactly as their leaders do and nowhere else (the franchise partition, Oct 10 2026); the **company tier** sets the standard. `leadsHere()` (`features/relay/leads.ts`) is the one app-side answer to "runs this studio" and mirrors `trainerLeads` in the rules. Operations is reachable by studio leaders and above (head trainer and above, AJ, Sep 18); the grant opens My Studio's leader sections, not Operations; Operations → Staff & Roles is read-only for the studio tier, with a door to My Studio → Team, and owners and administrators keep its editor (AJ, Sep 27 2026); the **Admins dashboard** is administrators (`Admin`, `Founder`) only — corporate staff who set up studios and set the standard, above the franchisees. **Always on, whatever you touch** (each is spelled out in full in that file):

- **A screen holding typing registers with `useUnsavedChanges`,** and any new way of switching screens, tabs or sections asks the gate first (`useLeaveGuard` or a leave scope), or the typing vanishes unannounced. See `src/features/unsaved-changes/README.md`.
- **Never block a save.** End Session confirms; it does not refuse. Only `performed` sets count toward any average - read outcomes through `src/lib/set-outcome.ts`.
- **Firestore refuses `undefined`.** Strip it before a write (`withoutUndefined`).
- **A new query needs its index, and a tap on the floor never awaits a write.** `firestore-indexes.test.ts` prints the index entry a query lacks; Start, Save and Discard issue and move on.
- **Use the Auth uid, not `authTrainer.id`,** for anything a rule pins to the signed-in person. The two differ on older accounts.
- **Mindbody routes need `authedFetch`;** a plain `fetch` gets a 401. The web service has no Firestore admin key.
- **Write only what changed, never a whole object read back** (`changedPatch`, `useDirtyForm`): a field the screen never showed is never wiped, two editors don't undo each other, and `clients/{id}.renewal` belongs to the nightly job, which the rules enforce.
- **A menu item is not a gate, and a sign-out forgets the person.** A screen a role may not open checks on the screen (`mayOpenOperations`), not only in the menu; a module-level memory of what someone was doing registers `forgetOnSignOut` (`src/features/sign-out/`).
- **Two files whose names differ only by case are ONE file on Windows.** Before shipping: `git ls-files | tr A-Z a-z | sort | uniq -d` prints nothing.
- **Run the suite with `TZ=America/New_York`.** A date-only ISO string is UTC; a date-time with no zone is local.
- **A green typecheck, suite and build do not mean a screen mounts.** Only `*.render.test.tsx` files mount anything; add one for any component that does work during render or in a layout effect.
- **Never type a raw control or invisible character into source;** write the escape.
- **A deploy deletes the screen files an open app hasn't fetched.** A new `React.lazy` screen goes inside a `LoadBoundary` (`lazy-screens.test.ts` holds it), and nothing calls `window.location.reload()` itself: ask `features/new-version` (`whenToLoad`), which never reloads over a session, a send or typing, nor offline.
- On AJ's PC, Claude's Windows shell runs git, `tsc`, `vitest` and `vite` in a worktree whose `node_modules` is a junction to the main checkout's (`docs/KNOWN-TRAPS.md`, the worktree note); a Linux-side shell on the PC mount can't; the cloud container runs everything, `test:rules` included. **AJ's `test:rules` run is the one that counts.** Use `git --no-optional-locks` for read-only git commands on the PC mount: a plain `git status` leaves an `index.lock` that cannot be deleted without delete permission and blocks his next git command.
